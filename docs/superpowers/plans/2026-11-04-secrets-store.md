# Secrets Store Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** People store credentials once, either their own or a project's. Agents get them as environment variables on their machine, see only their names and descriptions in the prompt, and every value is blanked out of whatever comes back to MegooColab.

**Architecture:**
- **Storage:** a new `app/secrets` package keeps write-only secrets, encrypted with `app.core.crypto`. Personal ones are reached at `/api/secrets`, a project's at `/api/projects/{ref}/secrets`.
- **Delivery:** at dispatch, `agent_runs.service` works out the run's secrets (the agent owner's personal ones plus the project's, with the project winning on a name clash). It sends them in `run_start.secrets` to runners that advertise `secrets/1`, and appends a names-only "Secrets you can use" section to the prompt.
- **Runner:** sets the secrets on the agent process. Its single-token redaction becomes a list of value→label pairs, so values come back as `[NAME]`.
- **Server side:** the MCP middleware blanks the same values out of every tool call a run makes.

**Tech Stack:** FastAPI, async SQLAlchemy, Alembic, Fernet (`cryptography`), MCP server; Go runner; Next.js 16, React 19, TanStack Query, vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-11-04-secrets-store-design.md`

## Global Constraints

- **Name:** `^[A-Z][A-Z0-9_]{0,99}$` (capital letters, digits and `_`, starting with a letter, at most 100 characters).
- **Description:** 1–1,000 characters. **Value:** 1–32,768 characters (32 KB).
- **Write-only:** a value is never returned by any API, written to the audit log, logged, or shown on a page after it is saved.
- **Refused names** (spec goal 4: variables the runner or the agent programs rely on), each refused with 422 `secret_name_reserved`:
  - exact: `PATH`, `PATHEXT`, `HOME`, `USERPROFILE`, `SYSTEMROOT`, `SYSTEMDRIVE`, `WINDIR`, `COMSPEC`, `TEMP`, `TMP`, `TMPDIR`, `APPDATA`, `LOCALAPPDATA`, `PROGRAMDATA`, `PROGRAMFILES`, `SHELL`, `USER`, `USERNAME`, `LOGNAME`, `LANG`, `LC_ALL`, `PWD`, `TERM`, `SSH_AUTH_SOCK`, `XDG_CONFIG_HOME`, `XDG_DATA_HOME`, `XDG_CACHE_HOME`;
  - any starting with `MEGOO`, `ANTHROPIC_`, `CLAUDE_`, `OPENAI_`, `CODEX_`, `OMP_`, `GIT_`, `LC_`.
- **Precedence:** the agent **owner's** personal secrets plus the run's project's secrets. The project's win on a name clash, and the requester's personal secrets never count.
- **Blanking:** values of 4 or more characters are replaced with `[NAME]`, longest value first. The run's MCP token keeps its `[redacted]`.
- **Encryption:** `app.core.crypto.encrypt` / `decrypt` only.
- **Capability:** `secrets/1` (backend `SECRETS_CAPABILITY`, runner `CapabilitySecrets`).
- **Copy** (exact strings from the spec):
  - "Encrypted before it is stored. After saving, nobody can see it again — only replace it."
  - "Values shorter than 4 characters can't be blanked out of what agents send back."
  - The project page's line: "Every agent that works on this project gets these as environment variables on its machine, where its owner could read them."
  - The prompt section heading: `## Secrets you can use`.
- **Migrations** only against `megoo_migrate`. Never two pytest runs at once. No Prettier. `npm run gen:api` after backend schema changes.
- **Commits** end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. No version bumps.

## Review Focus

1. **A secret value that is a substring of another**, or that occurs inside a URL or JSON string: blanking replaces the longest values first, and replaces inside nested JSON strings. Pinned in Task 3 and Task 4.
2. **A value split across two streamed message chunks:** the runner's hold-back must keep a value whole across chunks for every secret, not just the MCP token. Pinned in Task 4.
3. **An agent whose owner lost access to the project:** the run gets no project secrets (the run is not dispatched anyway), and never another user's. Pinned in Task 2.
4. **A Windows runner:** `%NAME%` and `$env:NAME` in the prompt section, and `cmd.Env` merge order (a secret never overrides a refused variable even if the server sent one). Pinned in Task 2 and Task 4.
5. **A run resumed into an existing session:** the section is also added to `resume_prompt`, since a resumed agent sees only that. Pinned in Task 2.

### Task 1: Secrets: table, names, encryption, and the two APIs

**Files:**
- Create: `backend/app/secrets/__init__.py`, `models.py`, `names.py`, `schemas.py`, `service.py`, `router.py`

- Test: `backend/tests/secrets/__init__.py`, `test_names.py`, `test_api.py`

**Interfaces:**
- Produces:
  - **`Secret`** (table `secrets`):
    - `id`;
    - `user_id` (FK users, CASCADE, nullable) and `project_id` (FK projects, CASCADE, nullable), with a check that exactly one is set;
    - `name` String(100), `description` String(1000), `value_enc` Text;
    - `updated_by` (FK users, SET NULL), `created_at`, `updated_at`, `value_updated_at`;
    - partial unique indexes `(user_id, name)` and `(project_id, name)`.
  - **`names.check_name(name: str) -> None`** raises `HTTPException(422, "secret_name_invalid" | "secret_name_reserved")`.
  - **Schemas:**
    - `SecretIn{name, description, value}`;
    - `SecretPatch{name?, description?}`;
    - `SecretValueIn{value}`;
    - `SecretOut{id, name, description, updated_at, value_updated_at, updated_by: Named | None}`, with no value field.
  - **Personal routes** (each person only their own):
    - `GET /api/secrets` → `list[SecretOut]`
    - `POST /api/secrets` → 201 `SecretOut`
    - `PATCH /api/secrets/{id}` → `SecretOut`
    - `PUT /api/secrets/{id}/value` → `SecretOut`
    - `DELETE /api/secrets/{id}` → 204
  - **Project routes** (read: anyone who can read the project; write: `projects.router._managed`):
    - `GET /api/projects/{ref}/secrets`
    - `POST /api/projects/{ref}/secrets`
    - `PATCH /api/projects/{ref}/secrets/{id}`
    - `PUT /api/projects/{ref}/secrets/{id}/value`
    - `DELETE /api/projects/{ref}/secrets/{id}`
  - **Errors:** 409 `secret_name_taken`, 404 `secret_not_found`, 422 `value_too_large`.
  - **Audit** with `audit.record`:
    - actions `secret.created`, `secret.updated`, `secret.value_replaced`, `secret.deleted`;
    - data `{"name", "scope": "user" | "project", "project_id"?}`, never the value.

### Task 3: The server blanks secrets out of agents' MCP writes

**Files:**
- Create: `backend/app/secrets/blanking.py`
- Modify: `backend/app/mcp_server/auth.py` (`McpBearerAuth.__call__`)
- Test: `backend/tests/secrets/test_blanking.py`

**Interfaces:**
- Consumes: Task 2's `values_for_run`.
- Produces:
  - `blanking.blank(text: str, secrets: dict[str, str]) -> str` replaces each value of 4 or more characters with `[NAME]`, longest value first.
  - `blanking.blank_json(obj, secrets) -> obj` does the same recursively in every string of dicts and lists (keys untouched).
  - In `McpBearerAuth`, for a run token whose run has secrets:
    - read the whole request body from `receive`;
    - when it is JSON-RPC `tools/call` (or a batch containing them), replace `params.arguments` with `blank_json(...)`;
    - hand the app a replayed `receive` with the new body.

    Other requests, and personal tokens, pass through untouched.

- Test: `runner/internal/jobs/secrets_test.go`, `redact_test.go` (extend), `protocol_test.go`

**Interfaces:**
- Produces:
  - `type Masked struct{ Value, Label string }` (package `jobs`, also used by `acpclient`). The run holds `masks []Masked`:
    - the MCP token as `{token, "[redacted]"}`;
    - each secret with a value of 4 or more characters as `{value, "[NAME]"}`;
    - sorted longest value first.
  - The redactor, `heldBack`, `redactMap`/`redactValue`, `redactMessage` and `acpclient.scrub` all take `[]Masked`.
  - `finishRun`'s error and `answerSteer`'s error are also passed through them.
  - **Environment:** `spec.Env` gains `NAME=VALUE` for each secret, except names failing `^[A-Z][A-Z0-9_]{0,99}$` or reserved by the same list as Global Constraints. The runner keeps its own copy (`jobs/secrets.go` `reserved(name) bool`). The env is applied after `os.Environ()`, so the secrets win over the inherited environment, but never over a reserved name.
  - **OMP:** OMP run servers get the secrets in each server's `Env`.
  - Secrets are never written to disk: not to the run log (it goes through the redactor) and not to files.
  - **Fake agent:** step `{"say_env": "NAME"}` makes the fake agent say the value of the environment variable `NAME`, for tests.

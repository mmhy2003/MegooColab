MegooColab 0.27.0 adds triggers: "when this happens in the project, send this prompt to an agent". Each time the event happens, the agent gets a chat with your prompt and what happened, and gets to work without anyone asking it.

## New

- **Triggers.** A project has a new **Triggers** tab, after Crons. A trigger has a name, an event, a prompt and an agent. Each time the event happens, MegooColab starts a freestyle chat with that agent. The chat holds the prompt and a "What happened" block with the keys and links, so the agent can change code, open pull requests or manage the board as in any chat.
  - **Nine events:**
    - a task is finished;
    - a task is created;
    - a task is moved to a column you choose;
    - a task needs a person (its workflow escalates);
    - a sprint is started or completed;
    - an epic is completed;
    - a cron finds something (one cron, or any);
    - a pull request is merged into the default branch outside any task.

    Task events count stories, tasks and bugs, and can be narrowed to some of these types and to one label. Sprint events are offered only in projects with sprints.
  - **After the agent replies**, the chat ends by default. Each trigger can keep its chat open instead. A chat whose turn failed, or where the agent asked a question, stays open either way.
  - **Each trigger has a page** with its firing history: when it fired, what happened, which agent, and the result, with a link to the chat. **Try it** fires the trigger now on the newest thing that matches, so you can check the prompt.
  - **Pause and Resume** stop and restart a trigger without deleting it.
  - **Chats show where they came from.** A chat started by a trigger has a "Trigger" chip, and its first message names the trigger and the person it runs as. The Chats page has a "Chats started by triggers" switch to hide them.
  - **No loops.** Nothing a triggered chat does fires another trigger, and one trigger starts at most 20 chats an hour.
  - **Who can do what:** project managers and admins create and edit triggers, and members can see them. A triggered chat runs as the person who last saved the trigger.
  - **When a firing can't start** (no usable agent, the person it runs as is gone, or the hourly limit is reached), it is skipped and the history says why. The person it runs as and the project's managers can be told. If the agent is offline, the chat waits for it, like any chat.

## Upgrading

Pull and restart as usual. The update adds database tables for triggers and their firings. They are applied automatically when the server starts. There's no new `.env` setting, and the runner doesn't need updating. No trigger exists until a manager creates one.

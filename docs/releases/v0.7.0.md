MegooColab 0.7.0 adds chats with your agents, lets you tell an agent something while it works, and lists every runner command on **My agents**.

## New

### Chats with an agent
- **Chats** in the sidebar, and a **Chats** tab in each project. **New chat** asks for the project, the agent (any free agent you may use, or a specific one) and what you want done.
- A chat goes through the same steps as a task, as a conversation:
  1. The agent asks what it needs to know.
  2. It writes a design, and you approve it.
  3. It writes a plan, and you approve it.
  4. It builds the plan step by step, with reviews.
  5. It finishes the way the project is set to (merge or pull request).
- **What you type does what the chat is waiting for**, and the line under the box says which before you send:
  - while the agent asks a question, your message answers it;
  - while a design or plan waits for approval, your message asks for changes (**Approve** stays on the card);
  - while the agent works, your message reaches it straight away, without stopping it;
  - when the agent is stopped, your message starts it again;
  - after a round has finished, your message starts a new round.
- **Rounds.** After a round finishes, keep typing in the same chat to start another round that goes through every step again. The agent gets a summary of the earlier rounds and every instruction you gave. When the earlier round's pull request is still open, and the project has a repository, the new round builds on its branch.
- **Add this to the board?** When a round finishes, or you press **End chat**, MegooColab offers to add the round to the board as a task.
  - The title, a description of what was asked and done, and the column are filled in, and you can edit them.
  - **Create task** keeps the round's whole history (conversation, design, plan, reviews, pull request) and adds its plan steps as subtasks.
  - **No, just end it** leaves it a chat.
- **End chat** ends a chat for good. An agent still working stops, and whatever it committed stays on its branch. A pull request in code review keeps being followed.
- **Who sees a chat:** the person who started it, the agent's owner, the project's managers and admins. Until a chat is added to the board, it stays out of the board, backlog, sprints, task counts, search and the MCP task list. Links to it, in notifications for example, open the chat.
- **Knowledge Base and memory** learn from chats as they do from tasks: approved designs, plans and final reviews are filed, and memory picks up what was said and decided.
- **Dashboard:**
  - a new **Open chats** tile, with how many wait on you;
  - a **Chats** card listing open chats with what each is doing;
  - chats waiting on you in **Needs you**, and a chat's agent at work in **Running now**;
  - chats as a third colour in **Finished · last 14 days**.
- People get the usual notifications when a chat's agent asks something, needs an approval or finishes: the person who started the chat, and the agent's owner if that's someone else. The notifications open the chat.

### Tell the agent something while it works
- The comment box on a task has a **Send to <agent>** switch. Typing `@` lists the task's agent first, and picking it turns the switch on.
- A message for the agent reaches it in the session it is working in, without stopping it. If it isn't working, the message waits for its next run. Every later step (plan, build, review) keeps it in mind.
- A message for the agent is an instruction: when it conflicts with the approved design or plan, the agent follows the message and brings the plan in line.
- In Activity, a message for the agent shows as "you → agent" with a violet bar and what happened to it: read while working, waiting for the next run, or given at the start of a run.
- Only the agent's owner, the project's managers and admins can send one. Once the agent has read it, it can't be edited.
- Mid-run delivery needs runner 0.3.0. With an older runner, the agent gets the message at its next run.

### Every runner command on My agents
- The **Install the runner** card is now a **Runner** card with four tabs:
  - **Set up**: install, sign in, check and start the runner;
  - **Keep it running**: install and start the background service in one line, plus status, stop, start and uninstall;
  - **Update**: the update command, and how to restart the service;
  - **Troubleshoot**: the check command, where the log is, and signing in again.
- Every command follows the Windows / Linux & macOS switch. A **Runner commands** button next to **Add agent** jumps to the card.

## Improved
- **The comment box floats at the bottom of a task's drawer and page**, so you don't have to scroll to the end to comment. It settles under the last item when you reach it. The ↑ ↓ buttons and the "Following live" note move up so they never cover it. On a phone, an empty box is one line that grows when you tap it.

## Fixed
- Picking an `@` mention and typing straight on no longer scrambles the text.

## Upgrading

```bash
docker compose pull
docker compose up -d
```

- The database changes (messages for the agent, and chats) apply by themselves when the backend starts. As always, take a backup first (`docs/install.md`, section 13).
- Update your runners to 0.3.0 so agents read messages while they work. With an older runner, everything else works, and messages reach the agent at its next run.

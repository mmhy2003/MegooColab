MegooColab 0.4.0 lets you choose the model and thinking effort each agent runs on, and makes it easier to see where you are: the active menu stands out, browser tabs name the page, and a missing page has its own screen with a way back.

## New

### A model and an effort for each agent
- Each agent on **My agents** has a **Model** and an **Effort** beside its machine.
- New agents start on a default model: **Opus 5.5** for Claude Code and **GPT-6.1 Sol** for Codex. Existing agents get the same defaults with this update. Empty the model to use the program's own default.
- After an agent's first run, Model lists the models its Claude Code or Codex actually offers. You can also type any model name or alias.
- Effort lists the levels the chosen model supports, after **Model default**: for most current Claude models Low, Medium, High, Xhigh and Max. A model without an effort setting shows **Not adjustable**. Choosing a model that lacks the chosen level sets Effort back to Model default and says so.
- The **Add agent** dialog has both, starting from the program's default model and Model default effort.
- A run never quietly uses something else: if the agent doesn't offer the chosen model or level, the run stops before it starts work and says to pick another on My agents.
- A task's Activity says which model and effort each run used, for example "used the model Opus 5.5 with High effort". **Admin › Agents** shows each agent's model and effort.

### A page for addresses that don't exist
- An address with nothing behind it now shows a 404 page in MegooColab's own style, inside the sidebar and header, with the address you tried.
- **Go back** returns to the page you came from, or opens the Dashboard when there is no earlier MegooColab page (a link opened in a new tab). **Dashboard** is always there too.
- A project, task, or Knowledge Base document or space that has been deleted shows the same page. Opening a deleted task's own page used to stay on "Loading…".

### Page names in browser tabs
- Each browser tab now names what it shows, then MegooColab: "Projects · MegooColab", "PAY Board · MegooColab", "PAY-12 Fix login · MegooColab", "Users · Admin · MegooColab".
- A task opened in the board's side panel names the tab while it is open; the board's name comes back when you close it.

## Improved
- **The active menu stands out.** The sidebar's current item has a glowing cyan bar on its left edge, a soft cyan tint and bold text, also on the collapsed icon rail and the phone menu. The other items are muted and turn white when you point at them.
- **Links show their intended colour.** A site-wide rule made every link cyan, overriding links meant to be muted or white. Those now show as designed: the earlier parts of the header breadcrumb, inactive project tabs, "Incoming questions", and the names on Knowledge Base space and team cards.

## Fixed
- **Breadcrumbs always lead somewhere.** The **admin**, **settings**, **tasks**, **doc** and **entity** breadcrumbs pointed at addresses with no page and showed an error. They now open Admin › Users, Profile, the project's board, the Knowledge Base and Memory. Typing those addresses works the same way.

## Upgrading

```bash
docker compose pull
docker compose up -d
```

- **Update your runners to 0.2.0, ideally before the server.** Every agent now has a model, and choosing one needs runner 0.2.0. An agent whose computer still runs an older runner shows "runner too old to choose the model — update megoocolab-runner", and its tasks wait (they are not lost) until that runner is updated. See the runner 0.2.0 release for how to update.
- The first task an agent runs after its runner starts takes a few seconds longer while the runner learns which effort levels each model supports. It remembers them until it restarts.
- Database changes apply by themselves when the backend starts. As always, take a backup first (`docs/install.md`, section 13).

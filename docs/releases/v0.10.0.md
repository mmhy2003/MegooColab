MegooColab 0.10.0 follows a task's pull request on GitHub, GitLab and Gitea from end to end. Its pushes, reviews and checks appear on the task. A review that asks for changes sends the task back to its agent. A project can also have an **agent review the pull request and merge it**. You can now **send images to agents**, and every page fits a phone down to 280 pixels wide.

## New

### Git providers, simpler to connect
- **Admin › Git › Add connection** asks only what it must. Pick the kind (GitHub, GitLab, Gitea / Forgejo), then **GitHub.com** or **GitLab.com** for the hosted services, which need no address, or **Self-hosted** with its server address. The webhook secret is gone from this form.
- The **Access token** field says what access the token needs, and links to how to make one for each host.

### Repositories picked from your provider, each with its own webhook
- In **Project › Settings › Repositories**, **Add a repository** lists the repositories the connection's token can see. Search them, pick one, and its name, address and default branch fill in. **Enter it by hand** is still there for a plain git server.
- Each repository gets **its own webhook address and secret**. The **Set up webhook** dialog has:
  - **Copy** buttons for the payload address and the secret, and the host's own steps;
  - **Create it for me**, which makes the webhook on GitHub, GitLab or Gitea when the token may manage webhooks;
  - **Make a new one** for a new secret;
  - the webhook's status: **not set up**, **working** (with when the last event came), or **failing**.
- Moving a repository to another connection, or removing it, removes the webhook MegooColab made on the old host. So does deleting the project or the connection.
- Webhooks set up with a connection's shared secret keep working. **Admin › Git** lists which repositories still use one, with **Remove shared secret** once they all have their own.

### A task's pull request on its Activity
- The task's Activity shows, one line each:
  - pushes to its branch ("pushed 2 commits · PR #42 updated");
  - the pull request opened;
  - comments;
  - reviews, with their line comments folded in;
  - checks passed or failed;
  - the merge or close, and who did it.
- Each line names who acted, with an **agent** tag when an agent did it, and the host. It quotes the comment or review, and links to it on the host.
- The bare "pr.status" lines are gone, and a merge shows once.

### Changes requested send the task back
- A new project setting, **Send the task back when changes are requested on its pull request**, turns this on. Then, while the task waits for its pull request to be merged:
  - a **changes requested** review, or a comment starting with **/fix**, sends the task back to its agent;
  - the agent reads every comment on the host, fixes the code, runs the tests and **pushes to the same branch**, with no new pull request and no force-push;
  - it can happen up to **3 times** per pull request, then MegooColab asks you.
- On GitHub only people with write access to the repository can send a task back this way.
- On GitLab, use a **/fix** comment, since its webhook doesn't say "changes requested".
- While the agent is fixing, the task shows who asked and the round, with **Don't send back** to stop it.

### Pull request review: None, Human or Agent
- **Require human code review before Done** becomes **Pull request review**, in project settings and in the admin default for new projects:
  - **None:** the task is Done when the agent finishes.
  - **Human:** the task waits until a person merges the pull request.
  - **Agent:** an agent reviews it on the host, and merges it when it approves.
- With **Agent**, choose the **Reviewer**: the task's own agent in a fresh session, or another agent of the project.
- **What the reviewer does:** it reads the pull request with the host's command-line tool (`gh`, `glab`, `tea`) and judges it against the approved design and plan. It posts its review from your account, with comments on lines, waits for the checks, then merges.
- **What follows:**
  - when it asks for changes, the task goes back to its agent, and the reviewer reviews the fix;
  - when it can't merge (branch protection, conflicts, failing checks), MegooColab asks you, with the reason.
- The review shows on the task as "review-bot **agent** approved PR #42 and merged it".

### Images for agents
- Add images to a chat message, a task comment, or **New chat**'s first message: with the image button, by pasting, or by dropping them. PNG, JPEG, GIF or WebP, up to 5 MB each and 6 per message.
- The agent sees them, as if you pasted a screenshot into it. Images show under their message (full size on click) and in the task's **Attachments**.
- Sending images to an agent needs **runner 0.6.0** on its machine; the image button says so until then. Agents working through MCP get a task's images from `get_task`.

### Chats laid out like tasks
- Each round of a chat shows its subtasks, design, plan, questions to other projects and attachments, then its conversation.

## Improved

- **Phones down to 280 pixels wide** (a Galaxy Fold's cover screen):
  - chats, the dashboard, search, the backlog, tables, labels, the editor and popups all fit, with no sideways scrolling;
  - an open chat gets the whole screen;
  - the task's comment bar is one line until tapped, and keeps your draft.
- **Agents run up to 5 tasks and chats at once** (was 3).
- **The finishing options and the review and documents settings explain themselves** where you choose them: what each option does and what each checkbox changes.
- **Thinking effort per AI job:** **Admin › AI › Models per job** has a thinking effort for each job, sent to models that take one.

## Fixed

- **Dreaming** no longer stops for days when a model's reply hits its token limit. A pair that fails is skipped and tried again later, and the rest of the memories go on.
- **Images:**
  - a run that fails before the agent starts hands its images back to the next run;
  - one run carries at most 20 MB of images, the newest first;
  - an image removed from a draft is deleted.
- **Phones:**
  - tables scroll again;
  - Back returns to where you came from;
  - the reply chooser keeps your comment open;
  - buttons are big enough to tap.

## Upgrading

Pull and restart as usual; the database is updated on start.

- **The review setting carries over:** projects that required human code review get **Human**, the others **None**.
- **Webhooks:** existing ones keep working. To give each repository its own, open **Set up webhook** on it. **Create it for me** needs a token that may manage webhooks (GitHub: Webhooks read/write; GitLab: `api` with Maintainer).
- **For agents to merge,** with **Pull request review** set to **Agent**, the GitHub or GitLab account the agent's machine is signed in to (`gh`, `glab`) must be allowed to merge.
- **Runner 0.6.0** is needed for images, and for a reviewer agent on the same machine and repository as the task's agent. Everything else works with runner 0.5.0.

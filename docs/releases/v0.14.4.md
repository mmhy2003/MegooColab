MegooColab 0.14.4 lets you filter the chat list by state and shows each chat's state at a glance, and lays out what a git connection's token needs in a card you can read.

## New

- **Filter chats by state.** Under the project filter on the Chats page (and on a project's Chats tab), a row of chips filters the list, each with how many chats it holds:
  - **All**, or **Active** (everything not ended, the default), so ended chats no longer crowd the list.
  - **Needs you:** a question to answer, a design or plan to approve, a code review, or an escalation to decide.
  - **Working:** the agent is building, reviewing, merging, or answering in a freestyle chat.
  - **Open:** the next message is yours: talking about the design, a freestyle reply, or a finished round. Chats whose runner is offline count here too.
  - **Ended.**
  - Your browser remembers the filter you pick. Counts follow the chosen project. A filter that leaves nothing says so, for example "Nothing needs you."

## Improved

- **Each chat's state at a glance.** Every row in the chat list starts with a mark for its state, and its state text takes the same colour: an amber dot when it needs someone, a turning cyan ring while the agent works (still if your system asks for less motion), a green ring when it's your turn, a pink dot when the agent's runner is offline, and a grey dot when it has ended. Ended chats' titles are dimmed.
- **What a git connection's token needs, laid out to read.** In Admin › Git, the small grey paragraph under the access token is now a card in normal-size text:
  - **One row per reason:** Follow pull requests (required), Set up webhooks in one click and Let an agent review and merge (optional).
  - **Each permission its own chip,** with its access: Read, or Read and write.
  - **GitHub: fine-grained or classic.** A switch shows each kind of token's permissions; the note that a fine-grained token can't read check runs shows with the fine-grained one.
  - **Create a token** opens the host's new-token page: GitHub.com or GitLab.com, or your self-hosted server's own once its address is in. A classic GitHub token comes with `repo` already ticked, a GitLab one with `read_api`. The host's guide stays beside it.
  - GitLab and Gitea get the same card, in their own words.

## Upgrading

Pull and restart as usual. Nothing else changes, and runner 0.8.0 stays current.

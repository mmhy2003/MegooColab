MegooColab 0.18.1 stops a workflow from getting stuck when an agent leaves its work uncommitted before a review.

## Fixed

- **Work left uncommitted goes back to its agent to commit before it's reviewed.**
  - **What went wrong:** a fix round could change files without committing them. The read-only re-review after it couldn't commit them and couldn't approve them either, so with no fix round left the task escalated.
  - **Now:** a build step, the final fix round or a pull request fix that ends with uncommitted changes goes back to the same agent, in the same session, to commit them (and, for a pull request fix, to push). The review starts only after that, and the commit doesn't use up a review round. The activity says, for example, "The fix round left its changes uncommitted: sent back to its agent to commit them".
  - **If the changes are still uncommitted,** the task asks you: "The agent left its changes uncommitted, so they can't be reviewed." Retry sends them back to the agent to commit again.
- **A read-only stage isn't blamed for changes it didn't make.** "The agent changed the repository during a read-only stage" now appears only when the agent moved the branch or left new changes. Uncommitted changes that were there before the stage started no longer count.
- **A task already stuck this way recovers with Retry.** It may be escalated as "The final review still had findings after one fix round" or as a read-only violation. Pressing Retry commits the uncommitted work first, then runs the review again. There's no need to commit by hand.

## Upgrading

Pull and restart as usual. There's no database change and no new setting, and runner 0.8.0 stays current. After upgrading, press Retry on any task stuck at review because of uncommitted work.

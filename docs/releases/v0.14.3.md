MegooColab 0.14.3 puts a task's details and agent workflow before the conversation on a phone, and stops asking GitHub fine-grained tokens for a "Checks" permission they can't have.

## Improved

- **A task on a phone: the conversation comes last.** On a phone or a narrow window (under 1024 px), a task's details and its agent workflow used to come after Activity and the comment box, so you scrolled past the whole conversation to reach them. Now:
  - **Details first, folded:** right under the title, one line shows what matters most: the status, who has the task (or "Unassigned"), its priority, and its sprint and due date when set. **Show all** opens the full list of fields in place, with "Reported by" at its end; **Hide** folds it again. Your browser remembers which you chose.
  - **Then the workflow,** always open, since it holds the buttons you act on (only on tasks that have one: stories, tasks and bugs).
  - **Then the task:** the description, subtasks, mockups, design, plan and the rest, as before.
  - **Activity and the comment box last.** The comment box still floats at the bottom edge while you read, and settles under the last comment.
  - **Unchanged on a wide screen:** the details column stays on the right and nothing folds.

## Fixed

- **GitHub tokens: no more asking for a "Checks" permission.** MegooColab's token help, its "GitHub refused the token" message and the install guide asked for **Checks: read**, but a fine-grained personal access token has no such permission: GitHub offers it only to GitHub Apps. Check runs, where GitHub Actions reports its results, can't be read with a fine-grained token at all. Now:
  - **The token help and the install guide** ask a fine-grained token for **Pull requests** and **Commit statuses** (read), and say that its check runs will show as unknown. A classic token with `repo` reads them, but it also allows writing.
  - **A GitHub pull request's "Checks unknown"** now says why: *"GitHub doesn't let a fine-grained token read check runs, where GitHub Actions reports. A classic token with repo shows them."* GitLab and Gitea keep their wording.
  - **Merges are still noticed** with a fine-grained token: only the pass or fail of the checks is missing.

## Upgrading

Pull and restart as usual. Nothing else changes, and runner 0.8.0 stays current. If you use a fine-grained GitHub token, make sure it has **Commit statuses: read**; to see GitHub Actions results on a private repository, use a classic token with `repo` instead.

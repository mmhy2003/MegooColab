MegooColab 0.15.0 lets a task's or chat's agent ask other projects about their code on its own, wait for the answer, and pick up again by itself.

## New

- **Agents ask other projects on their own.** When a task or chat involves another project, its agent asks that project instead of guessing. An agent of the other project reads its code and answers with file and line references, as before.
  - **Agents know whom they can ask.** Every task and chat run tells its agent which projects it may ask: the projects its agent's owner can see, with each one's key, name and the start of its description.
  - **The projects you name come first.** A project named by key or name in the task's title or description, or in the chat's messages, is listed first and marked "mentioned".
  - **When to ask.** The agent is told to ask when the work names a project, asks to integrate with, call, match or copy something that lives there, or depends on how that project does something.
  - **How many questions.** An agent may ask up to 20 questions per task, or per chat across all its rounds. These no longer count toward the asking person's own limit of open questions.
- **The agent waits for an answer it can't go on without, then picks up again by itself.** It asks with "wait", does what it can, and ends its turn saying what it asked.
  - **Waiting:** the task or chat then waits for the other project's answer, quietly; it isn't a "Needs you" item.
  - **Picking up again:** once every answer it needs has arrived, the agent continues in the same session with the answers and their sources, with no message from you.
  - **An early answer:** if an answer arrives while the agent is still working, it picks up again right away.
  - **Messages you send while it waits** reach the agent together with the answers.
- **Follow-up questions.** The agent can ask a follow-up to an earlier question of the same task or chat.
  - **Answered in context:** the other project's agent then sees the earlier questions and answers in that thread, and the agent that answered before is preferred.
  - **Shown together:** in a task's or chat's Questions section, follow-ups sit under the question they follow. The activity reads "asked ANS a follow-up to Q3 (Q4)".
- **You stay in control of a slow answer.** While the work waits, the task's workflow panel, and the chat above its message box, say whose answer it waits for and where each question stands, with three choices:
  - **Go on without it:** the agent picks up again now. It's told the answer isn't coming, carries on, and says which assumptions it made.
  - **Answer it yourself:** for those who may answer the question.
  - **Withdraw:** anyone who may act on the task can withdraw its questions, not only the person who asked.
- **You're told when it's worth knowing.** Once per question, the task's or chat's people hear when the question has gone to a person at the other project, and when it's still unanswered after 30 minutes. Admins change the minutes under **Settings → Questions**.

## Improved

- **The chat list shows a chat waiting for another project** as "waiting for ANS's answer", with an hourglass, under **Working**.

## Upgrading

Pull and restart as usual; the database is updated on start. Runner 0.8.0 stays current: nothing changes on the runner.

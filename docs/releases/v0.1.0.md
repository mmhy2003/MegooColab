The first release of MegooColab: a self-hosted place where people and coding agents plan, build and review work together.

## New

### Projects, boards and teams
- Set up your organization, its people and their roles (admin, manager, member, viewer), and teams that own projects.
- Plan work on live agile boards: epics, tasks and subtasks, labels, priorities, story points and due dates. Run sprints with burndown and velocity charts.
- Mark a project Active, Finished or Archived. Closed projects become read-only and their work stops. Admins can delete a project (after typing its key), and a sprint can be deleted, which sends its tasks back to the backlog.
- Each screen offers only the actions you may take. Closed projects are read-only, and an action blocked by the current state is greyed out with the reason.
- A dashboard on the home page: what needs you, running and queued agent work, your tasks, projects, agents, stages and recent activity, seen as Mine, My teams or Everything.

### Coding agents
- Connect Claude Code or Codex on your own computer with `megoocolab-runner` (released separately). Each task gets its own git worktree, so your working copy is never touched.
- An agent-assigned task moves through Brainstorm, Design, Plan, Build, Review and Done. People answer the agent's questions and approve the design and the plan before any code is written.
- Watch design mockups update live while you iterate with the agent, then approve the one you want.
- Choose the branch a task starts from. A production fix goes into its start branch and is merged back into the default branch, with both pull requests tracked until they are merged.
- Agents and people can ask a project questions about its code. The Knowledge Base and the memory are offered first; otherwise an online teammate's agent answers in a read-only session, citing files and lines.
- Agents use MegooColab's tools through a token-protected MCP server at `/api/mcp`.

### Knowledge and memory
- A versioned Markdown Knowledge Base with organization, team and project spaces. Compare revisions, link documents to tasks and to each other, and have approved designs and plans filed automatically.
- A collective memory learns short, sourced conclusions about your organization, teams, projects, people and agents. A nightly "dreaming" run consolidates them and keeps a summary card for each.
- One search box (Ctrl+K), with a full results page, finds tasks, documents, projects, teams, people, agents and questions as you type, forgives typos, and shows only what you may open.

### Git, notifications and administration
- Pull requests are followed on GitHub, GitLab and Gitea/Forgejo through read-only tokens and webhooks. When a project requires human code review, Done follows the merge by itself.
- Notifications in the app and by email: things that need you, assignments, mentions, an agent going offline mid-task, and unanswered questions. Each person sets their own preferences.
- Admin settings for email, AI providers and models, git connections, defaults for new projects, the dreaming schedule and search.
- Rate limits on sign-in, account pages, the API, AI calls, webhooks and live connections, with a clear "try again in N minutes" message.
- Install it as an app on your phone or desktop (over HTTPS).

### Installing and updating
- MegooColab now ships as ready-made Docker images: `ghcr.io/mmhy2003/megoocolab-backend` and `ghcr.io/mmhy2003/megoocolab-frontend`. Installing is: clone the repository, write `deploy/.env`, then `docker compose pull` and `docker compose up -d`.
- When a newer MegooColab is out, admins see an **Update** pill in the header, next to the bell, with the release notes and how to update. When an agent's runner is out of date, an amber ↑ appears next to the agent.
- Log lines from the backend and the worker start with their time, and terminals show the levels in colour.

## Upgrading

If you already ran MegooColab built from source, switch to the published images from the `deploy` directory:

```bash
git pull
docker compose pull
docker compose up -d
```

- `.env` keeps working as it is. Two settings are new, and both are optional:
  - `MEGOO_VERSION` pins a version (unset means the latest);
  - `UPDATE_CHECK=false` stops the server asking GitHub for new versions.
- Database changes apply by themselves when the backend starts. As always, take a backup first (`docs/install.md`, section 13).

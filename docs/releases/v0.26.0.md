MegooColab 0.26.0 stops tasks from getting stuck at the finish because of failing tests the branch didn't cause. Old and flaky failures no longer block the finish. You decide on the rest from a clear card, and an agent can fix its own failures in a reviewed fix round.

## New

- **Known failing tests don't stop the finish.** When tests fail at the finish, the agent first runs the failing ones again: a test that passes then is flaky. It then runs the tests that still fail on the commit the task branch started from: a test that fails there too was already broken. When every failing test is one of these, the task finishes as usual, and the pull request lists them under "Known failing tests".
  - To make any failing test stop the finish, turn off **Finish when the only failing tests are known ones** in the project's workflow settings. It's on by default.
- **A "Tests failed at finish" card for the rest.** When a test fails that the branch may have caused, the task waits for you on a card. The card lists the failing tests, what kind each one is and the agent's diagnosis.
  - **Finish anyway** delivers the work with those tests failing. It records who accepted them, and the pull request names them.
  - **Retry** runs the finish again.
  - **Pause** stops the task.
  - Telling the agent "go ahead anyway" in reply to its question now counts as Finish anyway, so the task doesn't stop again.
- **A fix round for failures the branch caused.** When the finish delivered nothing, the card also offers **Fix round**. The task's agent fixes the failing tests in a fresh run, a short review checks the fix, and then the finish runs again. A task gets up to 2 fix rounds. If the review still has findings, you decide whether to finish with the fix as it is or review it again. The finish agent itself still never changes code.
- **A test baseline at the start of Build.** Before step 1 changes anything, the agent runs the full test suite once and records which tests already fail. During Build, a failing test that isn't in that baseline is marked **new**: the agent is told at once and must fix it before completing the step, and the step reviewer treats it as a serious finding. A test that was already failing no longer holds a step up. The plan shows the baseline, and the test run lines mark new failures.
  - A baseline costs one extra suite run per task. To skip it, turn off **Record a test baseline when Build starts** in the project's workflow settings. It's on by default.
- **Bug tasks for known failing tests.** Next to each already-broken or flaky test that a finish reports, **Create bug task** makes an unassigned bug for that test with one click. Once a test has an open bug in the project, each later finish that sees the test links to that bug instead of offering a new one. Anyone who can edit the project's tasks can create one.

## Fixed

- **Settings → Notifications fits narrow phones.** On a 280-pixel screen, the Sound card's buttons now wrap below their text, instead of making the page scroll sideways.
- **Tasks already stuck at the finish can move on.** A task that delivered its work but stopped with "The agent ended its run without finishing the work" now shows the "Tests failed at finish" card, so you can click Finish anyway.

## Upgrading

Pull and restart as usual. The update adds database columns for the finish's test results, fix rounds, test baselines and failing-test bug tasks. They are applied automatically when the server starts. There's no new `.env` setting, and the runner doesn't need updating.

Both new project settings start on, for existing projects too. A task that is already past the start of Build keeps working as before. If you customised the Build, Review or Finish instructions, your agents still get the request to record a baseline. They aren't told the other new rules (how to sort failing tests at finish, and what a new failure means) until you add them to your texts; the defaults include them.

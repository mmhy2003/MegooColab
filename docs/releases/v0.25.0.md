MegooColab 0.25.0 lets an agent propose follow-up tasks with its design. When you agree with the agent to split a task into phases, the later phases no longer get lost: you review them when you approve the design, and approving creates them on the board.

## New

- **A design can carry follow-up tasks.** When you and the agent agree during Brainstorm or a design revision to split the work into phases, the agent lists the later phases as follow-up tasks with the design it submits. Each one has a type (story, task or bug), a title and a short description.
  - **You review them before anything is created.** The design approval view shows a "Follow-up tasks" block. You can untick a task, change its type, title or description, or add tasks of your own, up to 10. If the agent proposed any, the button under the live mockup becomes "Review follow-up tasks (n)" and takes you there.
  - **Approving the design creates the ticked tasks.** They land in the project's first column, unassigned, so no agent starts on them by itself, and in the same epic as the original task if it has one. Each links back to the original task and its approved design, and gets a "relates" link to it. The original task's activity shows each one that was created.
  - **The original task gets a scope note.** A line such as "Scope: phase 1 of 3 (per the approved design). Phases 2–3 → PAY-13, PAY-14." is added at the end of its description, so the plan, build and review runs know the later phases belong elsewhere. Your own text is left as it is.
  - **Rejecting a design creates nothing.** Each revision carries its own list, and only the version you approve counts.
  - **In a chat**, the tasks go on the chat's project board and link back to the chat.
  - **Agents still can't create tasks on their own** during a workflow. Every follow-up task is one you approved.

## Upgrading

Pull and restart as usual. The update adds two database columns for a design's follow-up tasks; they are applied automatically when the server starts. There's no new setting, and the runner doesn't need updating. If you customised the Brainstorm or Design revision instructions, your agents aren't told about follow-up tasks until you add it to your texts; the defaults include it.

MegooColab 0.12.0 brings two features. The **Secrets Store** gives agents API keys, passwords and tokens as environment variables, so you never paste them into a task, a chat or a prompt. **Agent Crons** have one of a project's agents do recurring work on a schedule, such as a nightly dependency check or a weekly summary. Each run leaves a report, and it can open tasks or keep a Knowledge Base document up to date.

## New

### Secrets Store
- **Save a credential once** and agents use it by name. A secret has:
  - a **name**, which is the environment variable (`STAGING_DB_PASSWORD`): capital letters, digits and `_`, starting with a letter;
  - a **description** of what it is, which the agent reads;
  - a **value**, stored encrypted.
- **Two kinds:**
  - **Personal secrets** in **Settings › Secrets**, managed only by you.
  - **Project secrets** in **Project › Settings › Secrets**, managed by the project's managers and admins. Members see the list but can't change it.
- **The value is write-only.** Once saved, it is never shown again, to anyone, and no page or API returns it. You can **replace** it with a new one (typed blind), edit the name and description, or delete the secret.
- **Which secrets a run gets:**
  - the **agent's owner's** personal secrets (never those of the person who started the run);
  - the **project's** secrets, when the run works on a project. Where a project secret and a personal secret share a name, the project's wins.
  - Every kind of run gets them: workflow runs and reviews, chats, Knowledge Base drafts, answers to other projects' questions and cron runs. A run answering another project's question gets that project's secrets.
- **The agent never sees a value in its prompt.** The prompt lists each secret by name and description, and tells the agent to use them by name (`$NAME`, or `%NAME%` / `$env:NAME` on Windows) and never to print, log, commit or write them to files.
  - **Runs that may run commands** (building, fixing, cron runs) can use the secrets in their commands.
  - **Read-only runs** (brainstorming, planning, reviews, answers, Knowledge Base drafts) still have the variables, so the MCP servers in the agent's own configuration can use them. Their commands can't read variables, and their prompt says so.
- **Values are blanked out of everything that comes back.** Wherever a value appears, it is replaced with `[NAME]` before MegooColab stores it. This covers the run's messages, tool calls and results, plans, file changes, summaries and errors, and everything the agent writes through MCP: designs, plans, reviews, Knowledge Base text, memory and answers. Trimmed, JSON-escaped and URL-encoded forms of the value are blanked too.
  - A value shorter than 4 characters can't be blanked safely, and the form warns about it.
- **Names that are refused:** a secret can't replace a variable the runner or the agent program relies on. That includes `PATH`, `HOME`, anything starting with `MEGOO`, the agent programs' own login and setup variables, variables that make a shell or runtime run code (`BASH_ENV`, `NODE_OPTIONS`, `LD_PRELOAD`, and similar), and proxy and certificate settings. The form says why.
- **Changes are recorded** in the audit log: adding, editing, replacing and deleting a secret, and handing secrets to a run. The log records names and who acted, never values. The list shows when each secret was last changed and by whom.
- **What it can't promise:** an agent that can run commands could still read a value it was given. The prompt forbids it, and blanking keeps anything that slips through out of MegooColab. A project's secrets reach the machine of every member whose agent works on the project. Both Secrets pages say this.

### Agent Crons
- **A cron** is scheduled work on one project. It has:
  - a **name** and a **prompt** (what the agent should do);
  - a **schedule** in standard five-field cron syntax, with a **time zone** (your browser's by default);
  - an **agent**: any free agent of the project, or one you choose;
  - **what it may do** with what it finds;
  - **when to tell you**.
- **Writing the schedule is helped and checked:**
  - **Presets:** every hour, every day at…, weekdays at…, every Monday at…, the 1st of the month.
  - **Field labels:** the five fields of the expression are shown labelled.
  - **Mistakes are named as you type** ("Hour must be 0–23 (you wrote 25)"), and **Save cron** stays disabled until it's fixed.
  - **A valid schedule is shown in plain words** ("At 09:00, Monday through Friday") with the next three run times in its time zone.
  - Schedules that would run more often than every 5 minutes are refused.
- **Each scheduled time runs exactly once, on one agent**, even with several backend processes.
  - **If the previous run is still going,** the time is skipped and noted.
  - **If no agent is online,** the run waits up to 15 minutes, then is skipped.
  - **After downtime,** MegooColab runs the cron once if the missed time was within the last hour. Older missed times are noted as skipped, never run in a burst.
  - **Daylight saving changes** are handled: a time that doesn't exist that day is skipped, and one that occurs twice runs once.
- **The run works in a throwaway copy of the code.**
  - **Fresh code:** before each run the agent's machine fetches the project's default branch from `origin` and resets the copy to it. If the fetch fails, the run uses the last fetched commit, and its report says which commit it used.
  - **Commands:** it may run any command (`npm outdated`, the test suite, commands that use secrets).
  - **Nothing is kept:** what it changes is thrown away afterwards. It never commits or pushes, and a run that makes a commit fails.
  - **Time limit:** a run is stopped after 30 minutes.
  - **Context:** it gets the previous run's report, so it can say what changed since.
- **What it may do,** chosen per cron. Every run writes a report. Then one of:
  - **Report only.**
  - **Report, and open tasks for real problems:** up to 5 tasks per run, labelled "from cron" and linked to the run's report. The agent checks the open tasks first. A problem that's already tracked is linked to its existing task instead of opening a duplicate.
  - **Report, and keep one Knowledge Base document:** each run rewrites one document in the project's space as a new revision ("Cron: <name>"). The document is created on the first run, and again if it is deleted.
- **Telling people:** choose any of "when it finds something", "after every run" and "when it fails". The cron's creator and the project's managers are notified through their usual channels, with a link to the report. Managers are always told when a run is skipped because no agent can work on the project.
- **Where it shows:**
  - **Project › Crons** lists each cron with its schedule in plain words, the next run, the agent and how the last run went. Managers get **Run now**, **Pause** and **Resume**.
  - **A cron's page** shows its settings and its run history, and each run's report: the summary, the findings with links to the tasks they opened or matched, and what was checked.
- **Who may:**
  - **Create, edit, run, pause and delete crons:** the project's managers and admins.
  - **See crons and their reports:** project members.
  - **Choosing an agent:** you may choose one only if you may use it on the project, as in chats.
- **Whose name it acts in:** a cron run acts as its agent's owner, so the tasks, comments and revisions it writes are credited to them with the agent.
- **What it can't do:** it reads only its own project's and the organization's Knowledge Base, and its own project's memory.
- **When it stops running:**
  - A cron keeps running after its creator leaves.
  - A finished or archived project's crons don't run.
  - Deleting a cron stops a run in progress.
  - If a chosen agent is deleted, its runs are skipped; MegooColab never quietly picks another agent.
- **The agent's instructions are yours to edit:** **Admin › Methodology** has a new **Crons** tab.

## Upgrading

Pull and restart as usual; the database is updated on start.

- **Runner 0.8.0** is needed on an agent's machine for that agent to receive secrets and to run crons.
  - With an older runner, everything else works as before: its runs get no secrets, and their prompt has no secrets section.
  - "Any free agent" prefers agents whose runner can run crons.
- **Keep `SECRET_KEY` unchanged:** secret values are encrypted with it, like Git tokens and Tool Hub secrets. Changing it makes stored secrets unreadable.

MegooColab 0.30.0 keeps agent runs alive when a runner is busy or briefly loses its connection. Several runs on one runner no longer drop it, and a short network drop or a server restart no longer fails every run on it.

## New

- **Runs survive a short disconnect.** When a runner's connection drops (the network, a server restart or a deploy), its runs keep going for a grace period of 60 seconds. When the runner reconnects, it says which runs it still holds and they carry on. A run it no longer holds fails as before, and so do its runs if it doesn't come back in time.
  - This needs runner 0.13.0. An older runner keeps today's behaviour: its runs fail as soon as the connection drops.
  - `RUNNER_GRACE_SECONDS` sets the grace period. `0` turns it off.
- **The database pool can be sized.** `DB_POOL_SIZE` and `DB_MAX_OVERFLOW` set how many database connections the backend keeps and may add in a burst (20 and 20 by default). The worker keeps 5 and may add 10.

## Fixed

- Two or more runs on one runner no longer close its connection with "keepalive ping timeout" and fail every run on it. The server now keeps reading the runner's connection while it saves the runs' progress, and saves updates that arrive together in one go.
- A run that finished just before its runner's connection dropped is now recorded as finished, not as "runner disconnected".
- Searching the Knowledge Base or Memory, and building an agent's prompt, no longer use up the database connections while waiting for the AI provider. Before, a busy server could make other requests wait 30 seconds and fail.
- Starting an agent's next run no longer holds the task and its workflow locked while the Knowledge Base and Memory sections of its prompt are looked up. Other changes to the task no longer wait for it.

## Improved

- When an agent's prompt is near its size limit, the Memory and Knowledge Base sections are now the first left out, and they come after the other context sections.

## Upgrading

Pull and restart as usual. Run `git pull` in your MegooColab folder first: the compose file now gives the worker its own, smaller database pool. Without it the worker uses the backend's 20 and 20, which is still under PostgreSQL's limit with the default settings. The new `.env` settings are all optional.

Update your runners to 0.13.0 to keep runs going through a short disconnect.

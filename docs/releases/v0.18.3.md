MegooColab 0.18.3 stops build steps from getting stuck over files git ignores, makes agent replies easier to read on a phone, and fixes the count of new entries on the ↓ button.

## Fixed

- **Ignored files no longer send finished work back to be committed.**
  - **What went wrong:** since 0.18.1, a step whose agent had committed its work could still be sent back with "left its changes uncommitted" if the run created or removed files that git ignores, such as `__pycache__` folders. The agent found nothing to commit, cleaned those folders up, and the task stopped with "The agent left its changes uncommitted, so they can't be reviewed."
  - **Now:** only changes that `git status` actually shows as uncommitted send the work back to its agent. Ignored files and MegooColab's own `.megoocolab/` folder don't count.
  - **Needs runner 0.8.2,** which reports what is left uncommitted. With an older runner, work goes straight to its review, as it did before 0.18.1.
- **Agent replies use the full width on a phone.** In tasks and chats, the time of an agent's reply used to take its own column on the right and squeezed the reply into half the screen. On a phone the time now sits next to the agent's name, and the reply's box starts under the row's dot. Event lines show their time after the text, and run summaries, fix-round summaries and pull request excerpts also use the full width. Tablets and larger screens look as before.
- **The ↓ button counts past 50.** When you scroll up in a busy task, the number of new entries on the ↓ button stopped at 50. It now shows the real number up to 99, then "99+". Chats show "99+" past 99 too.

## Upgrading

Pull and restart as usual. There's no database change and no new setting. Update the runner on each machine to 0.8.2 so that work left uncommitted is caught without tripping over ignored files. A task already waiting with "The agent left its changes uncommitted" continues when you press Retry.

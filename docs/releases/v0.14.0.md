MegooColab 0.14.0 adds **freestyle chats**: when you start a chat, you can have the agent just do what you ask, one reply at a time, instead of running the full workflow of design, plan, build and reviews. Use it for quick jobs such as cutting a release, renaming a module or checking something in the repository.

## New

### Freestyle chats
- **Choose when you start a chat.** New chat now asks **How should the agent work?**
  - **Workflow** (the default): it talks the request through, writes a design and a plan for you to approve, builds it step by step with reviews, then finishes as the project is set up to. This is the chat you know.
  - **Freestyle**: it does what you ask, one reply at a time, with no design, plan or reviews. It can change files, switch branches, commit and push when you ask.
  - Your last choice is remembered in this browser. A chat keeps its mode for its whole life.
- **Each message is one turn.** The agent:
  - works in the chat's own worktree on the agent's machine, starting on the chat's own `megoo/<KEY>-…` branch;
  - does what your message asks;
  - replies, then waits for your next message.

  It can create or switch branches, commit, merge, push and open pull requests when you ask, using your own git setup. If it moves to another branch, it switches back to the chat's branch before ending its turn, so that branch stays free for you.
- **Nothing is reviewed**, so the agent's reply says what it changed, which branch it's on, and anything left undone.
- **While the agent works,** a message you send reaches it straight away, as in any chat. If it can't be read straight away, the next turn starts on its own when this one ends.
- **The agent remembers the conversation.** When it continues its earlier session, it gets only your new message. When it has to start fresh (an agent program that can't resume, or a lost session), it gets the conversation so far: your messages and its own earlier replies.
- **It can still ask you something** when it truly can't go on. The question shows as a card, the same as in any chat.
- **A turn that fails doesn't retry or escalate.** The reason shows in the conversation, and your next message tries again. A freestyle chat is never stuck: every state ends with a message from you, or with End chat.
- **What you see:**
  - a **Freestyle** chip in the chat's header (where a workflow chat shows Talk → Design → Plan → Build → Finish) and in the chat list;
  - the state **working** or **waiting for your reply**;
  - the line under the message box: "<agent> starts working on your message."
- **One chat, one round.** Every message continues the same conversation; a freestyle chat never starts a "new round".
- **Ending it finishes it.** End chat asks first, as always, and stops a turn in progress. "Add this to the board?" then suggests **Done**.

### Notifications
- **"<agent> replied in <chat>"** when a freestyle turn ends, and **"<agent> couldn't finish in <chat>"**, with the reason, when it fails. They go to the person who started the chat.
- In-app by default. Turn on email, push or Telegram in **Settings › Notifications** under "An agent replied in my freestyle chat".
- **A freestyle chat waiting for your reply isn't on Needs you,** isn't counted as waiting, and isn't marked NEEDS YOU: waiting for you is normal there. A question from the agent still is.

### Methodology
- **Admin › Methodology** has a new **Chats** card holding the **freestyle** text: what the agent is told in a freestyle turn. Edit it like the other texts; every save creates a new version.

## Upgrading

Pull and restart as usual; the database is updated on start (existing chats stay workflow chats). Runner 0.8.0 stays current: freestyle needs no runner update.

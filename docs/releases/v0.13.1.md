MegooColab 0.13.1 fixes rounds that stayed on **Needs you** after an agent had already reviewed and merged the pull request. MegooColab now waits quietly for the merge to show on the git host, finishes the round when it does, and says in plain words when it can't read the pull request.

## Fixed

- **An agent's merge no longer asks you to review it.** When a project lets an agent review and merge its pull requests, the round used to wait as if a person still had to merge, so the chat or task kept showing on **Needs you**. Now the round says **Agent merged · confirming** (a chat says **merging · PR #n**) and finishes on its own once GitHub, GitLab or Gitea shows the merge.
  - **Nobody is pinged:** this wait stays off **Needs you**, off the board's NEEDS YOU marker and out of the notifications.
  - **It's fixed for both chats and tasks.**
  - **You can finish it yourself:** **Mark merged** sits under the "confirming" line if you know the merge went through.
- **A token without checks or reviews access no longer hides the pull request.** If a token could read the pull request but not its commit statuses, checks or reviews, MegooColab used to give up on the whole pull request. That's why the merge was never noticed. It now reads what it can: the merge still counts, and the missing part shows as "Checks unknown" or "Review unknown", with the permission the token lacks.
- **When an agent's merge can't be confirmed, you're asked once, clearly.** The round stops with "The agent merged the pull request, but MegooColab couldn't confirm it." and gives the reason. Its **Mark merged** button finishes the round. **Retry** checks the pull request again after you fix the token. This happens:
  - right away when the git host refuses or rejects the token, or can't find the repository;
  - after three failed reads for passing problems, such as the host being unreachable;
  - when the pull request is still open ten minutes after the agent merged it;
  - when the pull request is no longer followed, for example because its git connection was deleted.
- **Ending a chat leaves an unconfirmed merge to finish on its own,** instead of stopping a round that's only waiting for the git host.
- **Rounds stuck on this today are moved over on upgrade.** Rounds already waiting on an agent's merge come off **Needs you** and switch to the quiet "confirming" wait. Those whose merge is already visible then finish.

## Improved

- **Pull request read problems are said in words.** A pull request badge that can't be read shows **PR · can't read**, and the task explains why. For example: "GitHub refused the token (forbidden)", with the permissions it needs, or "The token can't see this repository or pull request."
- **Repository settings show read problems too.** A project's repository list says when its pull requests can't be read, or can only be partly read, so a missing permission is visible before a round gets stuck.
- **The GitHub token help lists every permission MegooColab reads with.** A fine-grained token needs Contents, Metadata, Pull requests, Commit statuses and Checks (read). A classic token needs repo.

## Upgrading

Pull and restart as usual; the database is updated on start. Runner 0.8.0 stays current.

- **GitHub fine-grained tokens:** add **Commit statuses: read** and **Checks: read** to see checks on pull requests. Without them, merges are still noticed, but checks show as unknown.
